## Selection and outcome boundaries

`ttf-parser::Face::glyph_svg_image(glyph_id)` returns `self.tables.svg.and_then(|svg| svg.documents.find(glyph_id))` (`lib.rs:2228–2242`). `SvgDocumentsList::find` picks the **first** document record whose inclusive glyph-ID range contains the glyph, then `get` takes the record's byte offset/length from the SVG document list (`tables/svg.rs:64–89`). `SvgDocument<'a>` borrows raw bytes and exposes the inclusive `start_glyph_id`/`end_glyph_id`; ttf-parser explicitly does not validate, render, or decompress those bytes (`9–24`, `lib.rs:2231–2237`). No font-level SVG viewBox or glyph-specific node is chosen there.

`DatabaseExt::svg` (`flatten.rs:349–376`) enters `with_face_data`, parses the selected face, gets `glyph_svg_image`, then calls `Tree::from_data(image.data, &Options::default()).ok()?`. If `start_glyph_id == end_glyph_id`, it returns `Some(Node::Group(Box::new(tree.root)))` for the **whole parsed root**, regardless of its renderable child count. If the record covers multiple glyphs, it searches the converted, renderable tree for ID `glyph{decimal glyph_id}` with `Tree::node_by_id`, logs if absent, clones the selected `Node`, and returns it. `node_by_id` traverses renderable root children and nested groups, not arbitrary XML/defs nodes (`usvg/src/tree/mod.rs:1612–1622,1704–1718`). It does not synthesize the requested glyph ID or try a second record.

`Cache::fontdb_svg` caches both `Some(Node)` and `None` by `(fontdb ID, GlyphId)` and clones the result (`converter.rs:46–93`); explicit font variation settings do not appear in that key. Distinguish these outcomes in shared preparation even though Source's `Option` erases several reasons:

| Stage | Source outcome | Observable continuation |
| --- | --- | --- |
| No font data/face parse, no SVG table or matching/in-bounds record | `None` through `?` | Try raster, then ordinary outline. |
| Gzip/UTF-8/XML/size failure, element-limit failure, or other `Tree::from_data` error | `.ok()?` becomes `None` | Same raster/outline continuation; Source does not expose the error to caller. |
| Multi-glyph record parsed but `glyphN` absent from **converted renderable** tree | warning then `None` | Same continuation; absence can include XML node eliminated by conversion. |
| Single-glyph record parses to an empty tree, or found `glyphN` node is empty | `Some(Node)` | SVG branch wins; no raster/outline fallback merely because nothing paints. The later `flatten` final nonzero stroke-bbox check can still return `None` for an all-empty text result (`flatten.rs:169–180`). |
| Valid selected node with paint | `Some(Node)` | It is nested under `glyph.svg_transform()` and inserted in appearance order. |

The distinction matters because a native gap in SVG asset conversion is not equivalent to Source `None`; whether/how to support a resource operation is a root policy question. This audit does not mandate a particular API or fallback rule beyond recording the Source outcome.

## Actual asset decoding and appearance context

`Tree::from_data` checks only the leading gzip magic bytes `1f 8b`; that branch runs `flate2::read::GzDecoder::read_to_end` and then UTF-8 validation. Other bytes are validated as UTF-8 directly (`parser/mod.rs:97–109,166–175`). Malformed gzip, bad UTF-8, malformed XML, invalid size, and element limit are explicit parser errors (`29–76`), but `DatabaseExt::svg` collapses them to `None`. The font asset uses **`Options::default()`**, not the outer Mermaid normalizer options: default 96 DPI, Times New Roman 12px, language `en`, default size 100×100, no `resources_dir`, an initially empty font database and default font resolver, no injected stylesheet (`options.rs:14–135`). The font asset can itself contain CSS, and usvg resolves its attributes/inheritance before conversion (`svgtree/parse.rs:226–527`).

The asset's root width/height/viewBox/preserveAspectRatio are resolved by `convert_doc`/`resolve_svg_size` (`converter.rs:348–467,489–565`). A viewBox creates a root transform; absent relative dimensions/viewBox use the default-size fallback and later bounding-box restoration. The selected single-record root keeps that converted structure; a multi-record selection retains only the converted `glyphN` subtree, so document-level viewport behavior already baked into ancestor groups cannot be assumed to survive subtree selection. This requires direct Source-tree comparison before choosing a typed representation. `PositionedGlyph::svg_transform()` returns its normal `transform()` (span × cluster × font-size/upem × glyph transform), whereas ordinary outline and COLR use a further Y-flip (`layout.rs:57–75,132–141`). The flatten branch wraps the selected node in that SVG transform and recalculates bounds (`flatten.rs:91–105`). Neither backend should derive or apply a second font placement transform.

An embedded glyph document is parsed as its own SVG document. Its CSS, fill/stroke, opacity, groups, gradients, patterns, clip paths, masks, filters, embedded images, and any internal text are processed inside that document before the selected `Node` is spliced into the outer text group (`converter.rs:348–467,739–869`). Internal text may yield no appearance with the default initially empty font database. For `currentColor`, `convert_paint` resolves the asset node's inherited `color`, defaulting to black when absent (`style.rs:189–202,243–251`); Source does not pass the outer Mermaid text `color` into this independent `Options::default()` parse. Ordinary outline batches use the span's fill/stroke/paint order (`flatten.rs:24–45`), while the selected SVG node brings its already-resolved own paint. A typed preparation layer must retain this distinction and not recolor the SVG asset with the surrounding span by default.

Asset `<image>` content can reach JPEG/PNG/GIF/WebP resources, SVG/SVGZ data URLs, and local file references via the **default** `ImageHrefResolver` (`image.rs:28–117,279–335`). Nested SVG data uses `Tree::from_data_nested`, which disables string/external image resolution inside that nested document but forwards data URLs (`parser/mod.rs:112–143`). The first-level font asset's `Options::default()` resolver can read relative paths from the process working directory because `resources_dir` is `None`; the outer normalizer's `resolve_string = None` does **not** reach this inner `Tree::from_data` call. This is a source fact and a resource-policy decision for root, not authorization to add filesystem access to the native path. Image conversion also computes intrinsic size, preserveAspectRatio mapping, optional slice clip, and nested groups (`image.rs:132–277`). Filter, mask, clip, pattern, paint-server and image references may be reachable from any selected root/subtree; `convert_doc` resolves and collects resources before the node is cloned (`converter.rs:397–464`). Cloning a selected node carries its resolved referenced resources, not the original raw XML ID lookup context. A typed scene must account for nested resource ownership and lifetime, not just copy shape outlines.

The Folia normalizer entry points differ: `folia_mermaid_render` renders a Mermaid SVG, creates outer options (Arial, system fonts if text, data-URL image resolver, string-image resolver disabled), and parses that **diagram** once (`normalizer/src/lib.rs:153–181,263–335`). `expand_embedded_svg_images` is called by the generic `folia_svg_normalize` path (`221–259`), not by `folia_mermaid_render`; it is not the font SVG asset loader. Regardless, `flatten.rs:349–376` creates fresh `Options::default()` for the font asset, so outer language, font size, loaded system fonts, stylesheet and image-resolver restrictions do not automatically apply there. This is precisely why actual font SVG asset parsing must be audited separately from the banned diagram/COLR bridge.

## Fallback and draw order

For each positioned glyph, `flatten.rs:79–159` checks COLR first, then font SVG, then raster, then outline. A successful COLR result wins even when visually empty, per root's COLR policy. A successful font SVG `Some(Node)` flushes the pending ordinary-outline batch with `push_outline_paths`, appends one group containing the selected node under `glyph.svg_transform()`, and continues. Raster does the same flush; ordinary outlines accumulate in `span_builder` and flush at the end of the span. COLR append does **not** flush a pending ordinary batch, so interleaving COLR has the source ordering quirk already frozen by root; the SVG branch's own flush must remain. Per span, overline and underline precede glyph output, line-through follows; `flatten` computes final group bounds and can discard the entire text group if stroke bounds are zero (`48–180`). Source glyph order, appearance insertion order, and semantic cluster order must remain distinguishable.

## Current native gaps and preparation boundary observations

`third_party/mermaid-rs-renderer/src/scene` presently has `GlyphAppearance::FontOutline | Geometry(Vec<GlyphLayer>) | Image` and a flat glyph-layer list (`text.rs:53–71`), `SceneNode` for Shape/Text/Image/Group (`mod.rs:60–90`), paints limited to solid/two-point linear (`paint.rs:16–46`), and image MIME limited to PNG/JPEG/GIF/WebP (`text.rs:25–42`). A full selected usvg font SVG subtree can contain nested groups, local transforms, opacity/isolation/blends, radial gradients/patterns, masks, filters, clipping, nested SVG images and resources. The flat glyph appearance and current D2D paint/image support cannot represent all reachable operations. Even a shape-only selected asset needs the exact parsed root/subtree, placement transform, fill/currentColor inheritance, bounds, and paint-server ownership; retaining the raw SVG bytes as an `ImageMime` is not equivalent to a completed shared scene.

The shared typed preparation boundary therefore needs to record which font/face/glyph and SVG document record was selected, borrowed-byte lifetime during decoding, parse result versus successful empty node, selected `glyphN` identity, completed normalized subtree and owned resource graph, asset-local style/currentColor and viewport transform, outer glyph placement, bounds, and the exact flush/insertion order. It also needs provenance for raw parser errors that Source collapses to `None`, without changing the Source's fallback outcome. All renderable operations chosen for the native scene need explicit shared representation or a root-approved resource policy; neither SVG nor Direct2D should independently parse/shape/select fonts or reinterpret asset-local paint. This audit intentionally does **not** choose whether raw SVG font assets may be parsed in shared preparation, how filesystem references are handled, or any concrete schema/API. Those decisions and Source verification belong to root.
