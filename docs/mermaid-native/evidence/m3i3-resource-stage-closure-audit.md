M3i2 already projects `Transform` (46) through the gradient context; a pattern may populate that *same* field differently, but the stage body is not newly missing.

## Storage, aliasing, stride, tail, and lifetime rules

`highp::Pipeline<'a,'b>` borrows immutable `PixmapRef<'a>`, mutable `SubPixmapMut<'b>`, immutable `MaskCtx<'a>`, value `AAMaskCtx`, and mutable `Context` (`highp.rs:28–47`); lowp has no source pixmap (`lowp.rs:41–59`, `mod.rs:501–540`). `RasterPipelineBlitter<'a,'b>` owns the compiled three pipelines but borrows source, clip mask, and mutable destination for its lifetime (`blitter.rs:19–35,196–210`). `SubPixmapMut` is `&mut [u8]`, `size`, `real_width`; its RGBA `pixels_mut()` casts that storage (`pixmap.rs:577–587`). `SubMaskRef` is borrowed `&[u8]`, `size`, `real_width` and yields borrowed `MaskCtx` (`mask.rs:391–403`). The normal blitter rejects clip-mask/destination visible-size mismatch (`blitter.rs:36–44`) before running. Source RGBA and destination mutable storage may be separate borrows; a caller must not manufacture an overlapping immutable/mutable alias to run original stage pointers. The fused source-over stage, by contrast, *intentionally* obtains one mutable destination pixel slice, reads then writes it in order (`highp.rs:669–689`, `lowp.rs:534–553`).

`SubPixmapMut::offset=real_width*dy+dx` is in **pixels** for RGBA helpers but in **bytes** for U8 mask helpers (`mod.rs:172–216`); `MaskCtx::offset=real_width*dy+dx` is in mask bytes (`mod.rs:239–250`). The rectangle run loops each row, high width 8 / low width 16; full program handles complete vectors, tail program handles `1..width-1` at row end (`highp.rs:146–199`, `lowp.rs:165–217`). Compiler substitutes exactly the five destination-dependent full/tail pointers and appends `just_return` (`mod.rs:411–480`). Crucially `MaskU8` reads only `tail` lanes even on full runs; `Gather` and filtered pattern sampling still execute full vector lanes for a tail, so their source coordinate/memory safety must be valid for all lanes; `gather_ix` clamps each to `[0,width/height−1 ULP]` (`highp.rs:317–331,873–882`). Destination load tails fill absent RGBA/A lanes with transparent/zero; destination store tails do not write absent lanes (`highp.rs:1283–1338`, `lowp.rs:774–836,294–345`). `AAMaskCtx.copy_at_xy` underflow is avoided only by producer-consistent `shift`, bounds, stride and the two-pixel coverage construction (`mod.rs:225–236`; `blitter.rs:298–331,372–382`).

## Real gradient consumer and blitter closure

Original `Gradient::push_stages` emits `SeedShader`, inverted/post-concatenated `Transform`, radial pre-stages, spread, two-stop/general lookup, optional `Premultiply`, then radial post-stage (`gradient.rs:106–259`; `radial_gradient.rs:234–313`). The frozen native `GradientProgram` covers this shader sequence only. To **render** it, Source `RasterPipelineBlitter::new` creates *three separately compiled pipelines* (`blitter.rs:79–193`): anti-horizontal coverage with `Scale1Float` or `Lerp1Float`; rectangle with `SourceOverRgba` fast path or `LoadDestination` + optional destination gamma expansion + blend + compression + `Store`; two-byte AA mask with `ScaleU8` or `LerpU8`. All three optionally insert clip `MaskU8` immediately after shader. The coverage branch depends on `BlendMode::should_pre_scale_coverage` (`blend_mode.rs:68–92`), blend stage on `to_stage` (`blend_mode.rs:94–126`), color-space destination expansion/compression on `color.rs:530–545`. Thus even a plain radial source-over rectangle still needs destination load/fused source-over/store and real destination lifetime; antialiased radial fill also needs coverage, mask, blend, and destination gamma sequencing. `blit_anti_h` skips zero runs, redirects opaque runs to `blit_h`, otherwise sets `current_coverage=alpha*(1/255)` and runs its coverage pipeline (`blitter.rs:263–296`). `blit_v`, `blit_anti_h2`, `blit_anti_v2` synthesize a two-byte `Mask` with row-byte 0/2/1, and `blit_mask` makes `AAMaskCtx` (`blitter.rs:298–331,372–382`). `blit_rect` can bypass all pipelines via RGBA/U8 memset (`blitter.rs:334–369`), so that path also belongs to actual image parity.

Source additionally has a distinct A8 `new_mask` blitter: `UniformColor` + `LoadDestinationU8` + coverage lerp + `StoreU8`, or direct U8 store/memset (`blitter.rs:214–254`). This lowp path is not needed merely to sample a gradient but is part of complete pipeline/blitter parity. Pattern paint has source-pixmap `Gather` or filtered stages, tiling/sampler context and opacity (`pattern.rs:97–186`); unlike a radial gradient it genuinely needs an immutable source pixel resource. Source picks actual source `PixmapRef` from Pattern and a 1×1 dummy for other shaders (`blitter.rs:196–200`). The dummy must not be mistaken for implemented pattern sampling.

## Executable original observer seam (for Root design review)

`RasterPipelineBuilder::compile` produces private `RasterPipeline.kind` with actual high/low function-pointer arrays and tail arrays (`mod.rs:395–499`). `RasterPipeline::run` passes them unchanged to original `highp::start` or `lowp::start` (`mod.rs:501–543`); `start` initializes registers and walks full/tail rectangles, calling `p.next_stage()` (`highp.rs:146–199`; `lowp.rs:165–217`). A Source-side, **append-only** observer inside the pristine crate could inspect the *already-compiled* pointer slice, interleave read-only capture functions after a selected original pointer in a temporary `Vec<StageFn>` (after the `Return` handling is accounted for), and invoke original `start` with real borrowed `PixmapRef`, `SubPixmapMut`, `MaskCtx`, `AAMaskCtx` and compiled `Context`. It must preserve pointer order, use the original stage pointer (including full/tail replacement), original register types, and original `next_stage` recursion; capture may read registers, cursor/tail and a separately observed destination snapshot, but must not mutate them. Compiling the baseline first avoids the `ArrayVec<Stage,32>` limit and avoids a capture stage changing original low/high selection (`mod.rs:347–368,395–480`). The prior M3i2 observer already demonstrates this arithmetic-stage seam; resource observations additionally need owned, initialized pixel/mask buffers kept alive across the `start` call and independent reset before each case. Full valid-paint observations must create the original `Paint`/`RasterPipelineBlitter` composition too, including memset/skip paths, because a controlled single-stage capture cannot certify caller ordering or pixel ownership. A standalone `MaskU8` all-zero case may terminate before capture by Source design; record termination/unchanged destination separately. Highp U8 and lowp null pointers must not be invoked as executable stages. Private `kind`, `Pipeline` fields and private stage bodies require an in-crate Source observer attachment; an external wrapper cannot legally read those states without visibility changes. This is an observation seam, not a proposed native API or substitute math.

No API/implementation/pixel acceptance decision is made here. In particular this audit does not advance the 34/70 Mermaid source-function tally, accept completed paint/WARP/D2D or Folia integration, or settle text/resource policy.
