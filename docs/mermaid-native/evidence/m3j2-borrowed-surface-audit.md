## Original borrowed storage and execution

`RasterPipelineBlitter<'a, 'b: 'a>` stores `Option<SubMaskRef<'a>>`, `PixmapRef<'a>` for the Pattern source or 1×1 dummy, and `&'a mut SubPixmapMut<'b>` for its mutable target, together with three independent compiled pipelines (`pipeline/blitter.rs:19–28`). Thus the blitter borrow is shorter than the target byte storage borrow, but persists across multiple `Blitter` calls. The Pattern image bytes must outlive the blitter; constructor lines 196–200 copy the `PixmapRef` borrow from the shader rather than copying pixels. For non-Pattern variants, those lines use the literal RGBA `[0,0,0,0]` 1×1 dummy. `Pattern::new` itself stores `PixmapRef<'a>` (`shaders/pattern.rs:67–94`). The native `PreparedPattern<'source>` and `SourcePixmap<'source>` already preserve this source borrow (`scene/prepare/pattern_types.rs`, `sampling/pattern/types.rs`); any blitter wrapper should carry it across all three compiled runs, not reconstruct it from output or make a short-lived temporary.

`PixmapRef::from_bytes` and `PixmapMut::from_bytes` accept premultiplied RGBA bytes with **at least** the needed length, rejecting zero/invalid `IntSize`, row width beyond `i32::MAX` bytes, arithmetic overflow, and short storage (`pixmap.rs:312–325, 461–475, 590–612`). Extra bytes remain part of their borrowed slice. `PixmapMut::as_subpixmap` takes the whole logical size and `real_width=width`; `subpixmap(rect)` intersects the requested rectangle, shifts the data-slice origin to the intersection's upper-left pixel, sets the **logical** `size=rect.size()`, and keeps **real** parent width (`pixmap.rs:532–553`). Its `SubPixmapMut` is `{data: &mut [u8], size: IntSize, real_width: usize}` (`pixmap.rs:567–587`), deliberately allowing a slice longer than the logical subregion. `offset(dx,dy)=real_width*dy+dx`, with RGBA pixel indexing for color and byte indexing for mask (`pipeline/mod.rs:172–215`). The logical width is therefore neither buffer length divided by height nor the destination stride. For RGBA, row bytes are `real_width*4`; for A8 mask target, row bytes are `real_width`.

The owned `Mask::from_vec` requires **exactly** logical width×height bytes (`mask.rs:95–105`); `Mask::new` allocates that many (`48–54`). Its `as_submask` and `submask` produce `{data:&[u8], size:IntSize, real_width:u32}`; a submask shifts the slice origin but retains parent width (`mask.rs:140–157, 391–404`). Mask-as-target uses the same `SubPixmapMut` shape but byte-per-pixel data (`mask.rs:160–177`). `RasterPipelineBlitter::new` checks only the mask's and target's **logical** widths and heights before any blend fast rejection; a mismatch logs a warning and returns `None` (`pipeline/blitter.rs:31–44`). A matching mask's stride may differ from the target's stride. `None` mask remains meaningful even if a `Some(mask)` has zero-valued pixels: the former skips `MaskU8` insertion and permits SourceOver/Source fast paths (`pipeline/blitter.rs:57–65, 86–88, 126–130, 163–165`). For each run, `Some(mask)` is converted to `MaskCtx{data,real_width}`, whereas `None` uses default empty data and zero width (`pipeline/blitter.rs:264, 361, 379`; `pipeline/mod.rs:239–250`). The existing native `MaskSurface` matches only the execution context, not the constructor's optional logical-surface identity.

Each original compiled pipeline owns its own mutable `Context`; `RasterPipeline::run` borrows `&mut self` and a fresh `&mut SubPixmapMut`, then dispatches high/low start (`pipeline/mod.rs:496–543`). High has a separate immutable Pattern `PixmapRef`; low omits it (`pipeline/highp.rs:145–175`, `pipeline/lowp.rs:165–192`). Both starts iterate destination-coordinate rectangles by rows, full 8/16-pixel tiles and one tail tile (`highp.rs:177–199`, `lowp.rs:194–217`). `ScreenIntRect` guarantees nonzero width/height and checked screen-coordinate bounds (`geom.rs:13–58`), but the original executor relies on its caller to clip rectangles to the logical target; the blitter constructor does not inspect future rectangles. The native `run_pipeline` already owns an independent `CompiledPipeline<PipelineContext>` and consumes `PipelineResources{source,destination,mask,aa_mask}` by value (`scene/prepare/pipeline_executor.rs`, `pipeline_executor_types.rs`). Its `DestinationSurface` and `MaskSurface` preserve bytes and real widths but do not carry logical dimensions; they are suitable transient execution views after a distinct typed blitter-boundary validation.

## AlphaRun and AA surface representation

Original `AlphaRun` is `Option<NonZeroU16>`, and `AlphaRuns` stores parallel `runs: Vec<AlphaRun>` and `alpha: Vec<u8>` (`alpha_runs.rs:15–24`). `AlphaRuns::new/reset` allocate `width+1` entries, place the first nonzero run at index 0, `None` terminator at index `width`, and alpha 0 at index 0; reset converts width to `u16` with `unwrap` (`26–34, 51–57`). The arrays are **sparse**: only the current run's start index is valid; the next start is at `current_index + run.get()`, and its alpha is read at the same index (`blitter.rs:32–45`). `blit_anti_h` reads `runs[0]`, then at each active index reads `aa[index]`; alpha 0 skips work, 255 delegates to `blit_h`, and 1–254 sets that pipeline's `current_coverage = alpha as f32 * (1.0/255.0)` before running a one-row rectangle (`pipeline/blitter.rs:263–295`). It advances **x**, `run_offset`, and `aa_offset` by the run length before looking up the next entry; it does not densify the arrays. Both slices are `&mut` in the `Blitter` trait even though this particular consumer only reads them (`blitter.rs:46–53`), because clipping/composition producers mutate them; `AlphaRuns::add/break_run/break_at` demonstrate that producer behavior (`alpha_runs.rs:59–232`). A native typed boundary should retain sparse parallel slices and `Option<NonZeroU16>` including the sentinel, not turn them into a dense alpha scanline or collapse zero-alpha with terminator. Constructor/observer cases should distinguish an empty run list (would index-panic), missing sentinel (would index-panic), zero run impossible in `NonZeroU16`, and a legal zero-*alpha* run.

`blit_v` creates a two-byte AA mask `[alpha,alpha]` with `row_bytes=0`, deliberately reusing the same row for all height; `blit_anti_h2` uses `[alpha0,alpha1]` with `row_bytes=2`, while `blit_anti_v2` uses the same two bytes with `row_bytes=1` (`pipeline/blitter.rs:298–332`). `blit_mask` projects `{pixels:mask.image, stride:mask.row_bytes, shift:(bounds.left + bounds.top*row_bytes) as usize}` and runs only the supplied clip (`372–383`); the separate logical destination mask, if present, still yields `MaskCtx`. `AAMaskCtx::copy_at_xy` has only `(offset,tail)` cases `(0,1)`, `(0,2)`, `(1,1)` and otherwise zeros (`pipeline/mod.rs:218–237`); `row_bytes=0` and the shift are observable, not conveniences to normalize away. Existing native `AaMask` carries precisely pixels/stride/shift, while `ResourceContext` and `PipelineResources` carry it to the accepted stage/executor implementations (`sampling/resources/types.rs`, `pipeline_executor_types.rs`).

## Candidate native seam for Root to freeze

1. A small `borrowed_surfaces_types.rs` could own a mutable **logical target** view: borrowed bytes, logical `width,height`, parent `real_width`, and explicit RGBA-versus-A8 target layout. A constructor/helper in `borrowed_surfaces.rs` could create whole/subregion reborrows with the original byte-offset and minimum backing-length rules. It should hand `DestinationSurface{data:&mut *target.data,real_width}` to each run only for that call, then release the reborrow; it must never clone target bytes or hold three simultaneous mutable views. Keep logical dimensions in the outer view for mask compatibility and clipping, not in the low-level accepted resource stage context.
2. The same narrow layer could own an immutable **logical mask** view with borrowed bytes, logical `width,height`, and `real_width`. The blitter constructor should accept `Option<LogicalMaskRef>` and compare logical sizes exactly as original lines 36–44, then convert to existing `MaskSurface` at each run. `None` must remain an explicit option through stage construction, even though the execution resource eventually uses a default-empty `MaskSurface`.
3. An `alpha_runs_types.rs`-sized boundary could expose borrowed parallel `&mut [u8]` and `&mut [Option<NonZeroU16>]` plus the original producer-owned vector form later. The blitter call should walk original sparse indices directly. A focused `blitter_alpha_runs.rs` could own only the consumer `blit_anti_h` method and its transparent/opaque/partial branches; producer mutation belongs to a later separate packet if needed.
4. `blitter_types.rs`/`blitter.rs` could own the eventual `BorrowedRasterBlitter<'shader,'blitter,'storage>` and constructor rejection order, carry one immutable Pattern `SourcePixmap<'shader>`, one exclusive logical target borrow, optional immutable logical mask, and three distinct `CompiledPipeline<PipelineContext>` values. Its methods should borrow the target transiently and dispatch the accepted `run_pipeline`. These are **candidate responsibilities**, not a request to freeze these exact names or lifetimes now.

The current `SourcePixmap::from_bytes` already validates borrowed contiguous premultiplied RGBA with extra bytes allowed (`scene/prepare/sampling/pattern/types.rs:5–18`). The current `DestinationSurface`/`MaskSurface` have no logical size; the present `PipelineResources` is an execution view, not a safe blitter constructor argument (`scene/prepare/sampling/resources/types.rs:6–16`, `scene/prepare/pipeline_executor_types.rs:4–8`). `PreparedShader::Pattern` borrows the source and `push_stages` receives one builder at a time (`scene/prepare/prepared_shader_types.rs`, `scene/prepare/shader_dispatch.rs`). No second scene CSS paint mode or duplicate PipelineContext is needed.

## Constructor outcomes and proposed independent Source observations

`new` checks mismatched logical mask/target sizes first (`pipeline/blitter.rs:36–44`), then returns `None` for Destination, and for DestinationIn only when shader is both opaque and solid (`46–55`). The opaque SourceOver→Source reduction requires `mask.is_none()` (`57–61`); a solid Source without mask may cache `color.premultiply().to_color_u8()` (`63–71`), while Clear without AA or mask caches transparent and changes to Source (`73–77`). The three builder passes each call the original shader's `push_stages`; a `false` return at anti-h, rect, or mask pass immediately returns `None` at its own line (`79–84, 119–124, 156–161`), preserving any earlier local work but constructing no blitter. Pattern inversion failure is one such producer outcome (`shaders/pattern.rs:97–104`). A stage capacity panic is not a `None`; `new_mask` constructs three white-uniform pipelines and returns `Some` without paint or optional-mask checks (`pipeline/blitter.rs:214–254`).

For Root's future Source witness, record logical target and mask dimensions separately from parent real widths and post-offset byte slices, `None` versus `Some(mask)` including all-zero content, Pattern source pointer/length/size and life across repeated calls, constructor outcome and warning, each of the three compiled stage/context records, then full target bytes and all three contexts after a sequence of mixed `blit_h`, sparse `blit_anti_h`, vertical/two-pixel AA, rect and mask calls. Include nonzero subregion origins, unequal parent strides with equal logical sizes, extra backing bytes, source and destination borrow separation, zero-row-byte vertical AA, and the exact rejected mask/blend/shader cases. Compare against actual unchanged original constructor and calls; do not derive gold from native logic or normalize sparse runs. This audit does not assert that such a blitter has already been accepted.
