# M4c COLR typed painter source audit — prerequisite only

Root review: source callback/state findings were checked against the pinned
COLR and flattening bodies. This report's proposed APIs and unsupported/fallback
policy are not adopted. Root's authoritative first-path policy is
`../colr-source-parity-policy.md`: reproduce observed Source appearance,
including sweep no-draw, composite reductions and batching quirks, while
distinguishing actual Source None/empty outcomes from native implementation
gaps. This read-only audit does not accept shared text or any backend.

This is a read-only source audit, not an accepted interface or implementation. It covers pinned `usvg 0.47.0` and `ttf-parser 0.25.1` as used by the normalizer. The proposed native path consumes `ttf_parser::colr::Painter` callbacks directly and emits typed scene content; it never manufactures or reparses a Mermaid SVG. Root owns architecture freeze, implementation, comparisons, and acceptance.

`ttf-parser` traverses COLRv0 layers in order, outline then solid (`colr.rs:928–951`); COLRv1 optionally pushes a glyph clip box, paints, then pops (`954–986`). Nested paint traversal recursively invokes callbacks. Its composite node paints a SourceOver backdrop in one layer, then the source in its requested mode, popping source before backdrop (`1763–1791`). The parser has a recursion stack with a 64-entry bound (`878–899`, `1840–1868`), so a typed painter need not invent a separate font graph traversal. Callback group/clip/transform nesting must be validated independently before publishing a scene node, because trait callbacks return `()` and cannot propagate `Result`.

`CompositeMode` enumerates Clear, Source, Destination, SourceOver, DestinationOver, SourceIn, DestinationIn, SourceOut, DestinationOut, SourceAtop, DestinationAtop, Xor, Plus, Screen, Overlay, Darken, Lighten, ColorDodge, ColorBurn, HardLight, SoftLight, Difference, Exclusion, Multiply, Hue, Saturation, Color, Luminosity (`ttf-parser colr.rs:579–635`). The source painter maps SourceOver and Screen through Luminosity (16 total) to SVG blend strings; Clear, Source, Destination, DestinationOver, SourceIn, DestinationIn, SourceOut, DestinationOut, SourceAtop, DestinationAtop, Xor, Plus are the 12 default-to-normal cases. A native implementation cannot treat those 12 as normal without explicitly accepting the source's lossy behavior. The existing Direct2D composer supports Normal and Multiply only.

## Paint parameters, transforms, IDs, and parser normalization

There is no fixed decimal precision in `colr.rs`. `Builder` formats callback `f32` coordinates with Rust `Display` into path commands (`17–41`); clip-box coordinates likewise use `{}` (`330–341`). XML writer attributes receive `f32` values for gradient coordinates, stop offsets, alpha fractions, and six matrix entries (`49–80`, `97–105`, `119–185`). RGB channels are written as integer `rgb(r,g,b)` and alpha separately as `f32::from(alpha)/255.0` for fill/stop opacity (`50–55`, `97–116`). Transparent colors retain RGB. The serialization round trip converts those shortest decimal strings through SVG attribute parsing to `f64`/`f32` as appropriate, so converting original `f32` directly to scene `f64` without matching the final parsed values may differ at precision boundaries. Identity transforms omit their attribute (`57–70`). Each glyph starts IDs at `lg1`, `rg1`, and `cp1`; linear and radial **share** `gradient_index`, clips have their own counter (`84–94`, `119–185`, `230–246`, `flatten.rs:378–415`). IDs are local to the reparsed glyph tree; a typed scene should use scoped stable handles rather than globally meaningful text IDs.

`write_gradient_stops` preserves iterator order and uses `gradient.stops(palette_index, face.variation_coordinates())` (`97–105`, `145–148`, `177–180`). The ttf-parser gradient APIs explicitly say callers must sort stops themselves (`colr.rs:388–405`, `452–470`, `510–529`); upstream does **not** sort. `ttf-parser` resolves CPAL palette including `0xFFFF` foreground and variation-adjusted alpha/offsets (`273–334`), so a typed painter must use the same resolved iterator, face coordinates, palette 0, and black opaque foreground to compare source appearances. Spread Pad/Repeat/Reflect maps to `pad/repeat/reflect` (`usvg colr.rs:71–81`). Source TODO notes COLR spread range should follow first/last stops, whereas emitted SVG applies spread at gradient endpoints (`125–130`). Preserve the observed SVG semantics for oracle parity or require an explicit root decision for full COLR semantics; do not silently lose the difference.

For linear gradients, source `x1/y1` are COLR `x0/y0`, and source `x2/y2` are COLR `x1/y1`; COLR's third point `x2/y2` is ignored with a TODO (`119–150`; ttf-parser `346–364`). Thus current source output is a two-point SVG linear gradient, even when the three-point COLR geometry matters. Radial maps outer center/radius from `x1/y1/r1`, focal center/radius from `x0/y0/r0` (`155–185`; ttf-parser `410–428`). Sweep has center/angles/extend/stops in `ttf-parser:474–529`, but source emits no path (`187–190`). The gradient transform is `outline_transform.invert().log_none(...).unwrap_or_default().pre_concat(current_transform)` after `ttf_parser`→`tiny_skia_path` conversion, then back to six f32 fields (`192–228`). On inversion failure it logs and starts from identity. Preserve exact multiplication/order and f32 stages. The path itself carries `outline_transform`; both path and gradient transform matter.

The artificial SVG is parsed with default options, then converted and postprocessed (`converter.rs:348–467`, including `update_paint_servers` at 443). The generated root has no explicit width, height, or viewBox; `resolve_svg_size` uses default viewport resolution (`489–552`). Source path strings go through `svgtypes::SimplifyingPathParser` and `tiny_skia_path::PathBuilder`, with numeric narrowing to f32 and possible partial path on parse failure (`shapes.rs:26–64`). Thus a typed path must model the *resulting* tiny-skia path semantics, not merely raw command text.

Gradient parser effects are appearance-significant:

* `convert_linear` uses emitted user-space coordinates/transform/spread; fewer than two stops collapse to a color (`paint_server.rs:48–82`, `539–552`). `convert_radial` does the same, collapses invalid/nonpositive outer radius to the last stop color, and clamps/normalizes focal radius through `PositiveF32` (`85–147`).
* `convert_stops` parses numeric or percent offsets, substitutes the previous value for other units, narrows and clamps each to [0,1], splits parsed color alpha, multiplies it by stop-opacity, removes the middle of three approximately equal offsets, moves a pair of near-zero offsets apart by `f32::EPSILON`, and shifts adjacent equal/decreasing offsets using `f32::EPSILON` (`277–404`). It does not globally sort arbitrary out-of-order stops. The native scene's current gradient builder rejects descending stops, so passing raw ttf stops directly would diverge.
* `convert_group` resolves `mix-blend-mode`, `isolation`, transform, and clip link; generated layer groups are preserved because `isolation:isolate` is explicit (`converter.rs:739–869`). Linked clips use default user-space units, transform, bounding-box calculation, and cache handling; invalid clips can cause the group to disappear (`clippath.rs:11–91`, `converter.rs:797–802`). The typed path needs equivalent validity/visibility handling, not just the clip polygon.
* `update_paint_servers` processes fill references and coordinate context after conversion (`paint_server.rs:554–759`, `760–924`). User-space gradients avoid object-bounding-box remapping, but the converted tree still carries normalized paint/clip/bounds. A typed substitute must define these final values before backend rendering.

These effects are the existing baseline's actual appearance, including its defects. They do not license a production path that drops unsupported paint operations.

Existing `Clip { geometry, transform }` and path commands are reusable. A general nested glyph subscene plus typed paints and compositing would be an architectural extension; this audit makes no schema edit. In particular, adding radial/sweep to `Paint` alone cannot encode `push_clip`/`push_layer` nesting or Porter-Duff operations.

## Proposed minimal typed boundary for root to freeze

One internal resolver entry point could take `(&ttf_parser::Face<'_>, GlyphId, palette_index: u16, foreground: RgbaColor)` and return `Result<Option<ResolvedColrGlyph>, ColrDiagnostic>`. `None` means no COLR glyph; an error means malformed/unsupported/invalid output and must not silently become an outline. `ResolvedColrGlyph` would own the callback-built outline paths, paint definitions/stops, and ordered nested groups; it must not borrow `Face`, `GradientStopsIter`, `XmlWriter`, or source font bytes. The font resource owner retains bytes for the callback's lifetime. The resolver should be called in the shared text/flatten stage, with the existing glyph placement transform applied at the same location as `glyph.colr_transform()`; D2D receives final typed appearance only.

A `TypedColrPainter<'face>` implementing the unmodified `ttf_parser::colr::Painter<'face>` can hold: current transform, captured outline transform and path validity, transform stack, nested clip/layer stack, sequential local paint handles, ordered output tree, and first diagnostic. Since callbacks cannot fail, the first error is latched; subsequent callbacks may maintain stack balance but publish nothing if any error occurred. Check that all stacks close and every emitted leaf has valid geometry/paint before committing the glyph. For parity with the pinned source, normalize the callback values in typed code using explicit f32-stage transforms, stop adjustments, group blend/isolation, clip validation, and final paint rules documented above. This is direct numeric/typed normalization; no SVG string or parser is part of production. A separate policy decision is required for the source's ignored linear third point, spread mismatch, sweep omission, and 12 degraded composite modes. Full support needs corresponding scene and Direct2D operations; until available, return a named unsupported diagnostic instead of an empty glyph, normal blend, or outline fallback.

Suggested diagnostics carry font identity/face index, glyph ID, COLR version if available, callback/paint kind, palette/variation selection, source operation index and nesting path, and failing numeric/transform reason. This distinguishes no COLR, invalid COLR graph, missing outline, unsupported sweep/composite, noninvertible transform, invalid clip, and parser-baseline mismatch. Preserve source provenance separately from display glyph cluster/range so the shared text resolver can identify a particular span without asking the backend to shape.

For independent comparison, use the pinned source's existing COLR→SVG→`Tree::from_data` only in an oracle/test harness, not production. Compare (1) callback event sequence and stack balance for v0/v1 fonts, (2) final normalized path commands/f32 bits, transforms, stop offsets/colors/opacities, gradient type/parameters, group order/isolation/blend, clip and bounds against the oracle tree, and (3) rasterized crops on WARP for opaque/transparent layers, interleaved normal/color glyphs, transform nesting, clip boxes, duplicate/out-of-range stops, degenerate radial radii, noninvertible transforms, all composite modes, sweep, and variable palettes. Classify known source-lossy cases separately from supported parity; report unsupported outcomes explicitly. This comparison is independent of the native backend's shaping and of the new typed painter's own serializer.

Open decisions for root: whether to reproduce the upstream flatten ordering quirk, whether source-lossy COLR semantics are accepted for the first supported subset or treated as unsupported, how to expand `GlyphAppearance`/scene group ownership, and which composite/gradient capabilities can be delivered together through D2D. No acceptance claim is made here.
