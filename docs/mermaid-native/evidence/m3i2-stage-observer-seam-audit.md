`RasterPipeline::run` is the Source production dispatch: match the private `kind` and pass its **already compiled** full and tail function slices plus `&mut self.ctx` to `highp::start` (also `pixmap_src`) or `lowp::start` (no source pixmap), with the caller's `ScreenIntRect`, `AAMaskCtx`, `MaskCtx` and mutable destination (`pipeline/mod.rs:501–542`). They set `p.functions` to the supplied full/tail slice and set `p.index=0`, `dx`, `dy`, and `tail` for each invocation. ## Append-only execution seam, without changing compilation

An observer could append sibling functions inside the **original** `pipeline/highp.rs` and `pipeline/lowp.rs` modules. This placement gives the callbacks lawful access to those modules' private `Pipeline` fields, `lowp::join/split`, and `ctx` without widening production visibility. A conceptual callback signature is `fn capture(p: &mut Pipeline)` in each module, matching its own `StageFn`; the callback only reads registers/context/location/pixels into an observer-owned record and then calls the **original** `p.next_stage()` to continue. That continuation advances `p.index` as every original stage does; the snapshot must not alter color registers, context, masks, resources or destination. Since a function pointer cannot carry a capturing closure, per-thread observer state or another explicitly scoped recorder is needed to tag and collect snapshots. Its lifetime must cover the synchronous `start` call and be cleared on both normal return and panic; nested/concurrent invocations need separation or an explicit rejection. This is an observation mechanism, not a proposed production renderer API.

An append-only helper in the original `pipeline/mod.rs` could inspect `RasterPipeline.kind` **after calling the original `RasterPipelineBuilder::compile`**, copy its chosen `functions` and `tail_functions` into separate `Vec<highp::StageFn>` or `Vec<lowp::StageFn>`, and interleave a capture pointer after each compiled stage pointer but **before** the original `just_return` pointer. It may also insert a first capture to observe pre-stage register state. Preserve the exact compiled pointer in every position, including the compiler's five actual tail substitutions (`mod.rs:424–439,457–472`); use the actual `kind` to choose the matching original `start`, never the native M3i1 projection or an observer recomputation of lowp eligibility. For example, a nonempty compiled `[S0,S1,just_return]` becomes `[capture_before,S0,capture_after_0,S1,capture_after_1,just_return]` in an **external Vec** for this observed call. Each capture records then calls `next_stage`. The original `S0`/`S1` bodies and the original `start` loop execute. A callback cannot be inserted *after* `just_return`, because that terminal never continues. Capture before Return and read the destination after `start` when final store/pixel outcome is required.

This sequencing preserves the original compiler's 32-slot control. Original builder pushes and `compile` still use their unchanged `ArrayVec<_,32>` and still panic at their original capacity boundaries (`mod.rs:66,366–368,412–417,449–454`). The longer observer-only `Vec` is created **after a successful original compile**, never inserted into the builder or its `ArrayVec`, and is passed to `start`'s slice parameters. It therefore cannot change original high/low selection, ordered compiled pointers, terminal insertion, or tail substitution. On a 32-stage compile panic there is no executable compiled pipeline to observe. The empty-list compile branch returns High with empty function slices and `Context::default()` (`mod.rs:395–404`); on a nonempty rectangle `start` would index an empty slice, so that case is compile-only observation, not an invented pixel result.

The helper's small `kind` match mirrors **only** `RasterPipeline::run`'s dispatch (`mod.rs:510–540`) to pass the interleaved slices to the original `highp::start`/`lowp::start`; it does not rewrite `compile` or either `start`. Because `RasterPipeline.kind` and compiled arrays are private to `pipeline/mod.rs`, an external test crate cannot obtain them by ordinary public API. Append-only module-local access is the narrow seam. The original compiled slices must remain available unchanged for pointer-label comparison and for an unobserved `run` pixel cross-check; the observer should not mutate them.

Both full and tail slices need their own interleaved copies. At a callback, `p.tail==STAGE_WIDTH` identifies a full chunk, while `1<=p.tail<STAGE_WIDTH` identifies a tail (`highp.rs:181–198`; `lowp.rs:198–215`); record the actual `dx`, `dy`, `tail`, precision and logical compiled operation position. `p.index` is the **next function slot after the callback pointer has been fetched**, so it is a cursor into the augmented function slice, not the gradient stop index. A recorder-side mapping from augmented slot to original compiled pointer/operation label avoids confusing repeated stages. A zero-area rectangle yields no callback. Because each `start` reuses one `Pipeline` across chunks/rows, records must be keyed by invocation coordinates and chunk width rather than assuming fresh register state at each row.

| --- | --- |
| Highp registers and position | In an append-only `highp.rs` callback, read `p.r,g,b,a` and `p.dr,dg,db,da` as all **eight raw f32 bit patterns** (not decimal-rounded strings), plus `p.index,dx,dy,tail` (`highp.rs:28–47`). For gradient stages this observes `x/y/t` or post-lookup float color according to the stage label; it does not assign a fixed meaning to `r/g` across every stage. |
| Lowp registers and position | In `lowp.rs`, read all eight `u16x16` register arrays exactly (`lowp.rs:41–59`). Before lookup these registers may hold bit-packed `f32x16` x/y through original `split/join` (`lowp.rs:255–266,871–896`); after lookup they are byte-valued u16 channels (`:602–647,713–730`). Tag the phase and, where applicable, use the original module's `join` only to **read** the x/y interpretation; preserve raw u16 bits as primary evidence. |
| Context and validity mask | `Pipeline.ctx` points at the actual `Context` (`highp.rs:33`; `lowp.rs:47`). Snapshot relevant `current_coverage`, transform, stop factor/bias/t-values/len and conical `p0,p1` at stage boundaries; read `two_point_conical_gradient.mask` as eight raw u32 lanes after the original highp mask stage (`pipeline/mod.rs:252–339`; `highp.rs:1076–1107`). | **General Gradient stop index is inaccessible** | Highp `idx: u32x8` exists only inside `gradient`, then is passed to private `gradient_lookup` (`highp.rs:916–978`); lowp `idx: u16x16` likewise exists only inside `gradient`/`gradient_lookup` (`lowp.rs:602–711`). Neither is stored in `Pipeline` or `Context`. A between-stage callback can capture t before and RGBA after lookup, **but cannot read the actual local `idx`** or pre-rounding lowp lookup floats. Recomputing index/search in the observer would be a formula-rewrite oracle, not Source execution observation. The same intra-stage limitation applies to `gradient_lookup`'s local gathered factor/bias vectors, lowp pre-u16 float results, vector `powf` intermediates, and individual sqrt/discriminant temporaries. A capture after one stage sees the committed registers/context and output pixels, not private temporaries of that stage. It can expose NaN, infinity and signed-zero effects in committed registers via raw bits, without claiming to explain every intermediate.

## Two distinct observation families

**Controlled raw stage execution:** append-only setup callbacks in the same highp/lowp module may initialize private registers and the original `Context` with exact bit-pattern inputs, then call `next_stage` so a single original stage pointer runs, followed by the read-only capture and original `just_return`. For lowp pre-lookup coordinates, setup can call the original `split` to pack f32x16 values; for highp it can load f32x8 lanes. Use original builder/compile to select precision (force-HQ only through the original flag), then insert setup **after** compile, so it cannot affect stage eligibility or capacity. This family probes stage-level nonfinite and boundary behavior that safe gradient constructors cannot express; it is not evidence that those inputs are reachable from a valid `Paint`. Some stages require real destination/mask/source resources or prior register/context values, and highp's U8 destination functions are intentionally unreachable (`highp.rs:292–307`); a raw one-stage probe must not assert a valid output for such unsupported isolated setups.

**Valid paint execution:** construct the original `GradientStop`/`RadialGradient`/`Shader` and `Paint`; let the original `Gradient::new`, radial `push_stages`, shader dispatch, and `RasterPipelineBlitter::new` establish stops, transform, `Context`, complete paint suffixes, final force flag and compiled High/Low pipelines (`gradient.rs:51–258`; `radial_gradient.rs:234–313`; `shaders/mod.rs:79–92`; `blitter.rs:30–211`). The original blitter stores distinct anti-horizontal, rectangle and mask pipelines (`blitter.rs:19–28,79–194`); its draw methods also set coverage/mask arguments and may take memset/fast-reject paths instead of running a pipeline (`:46–77,257–384`). An append-only observer in that module could access these private compiled members and call the observed `start` seam with the same resources and branch-specific parameters, while checking against an ordinary unobserved draw on an identical destination. It must label when no pipeline was run; it cannot silently replace original paint construction with native M3h `GradientProgram` fields or use a synthetic stage list to claim valid-paint parity. Duplicate draw-site argument setup is a potential observation drift point for Root to assess; a Source-body edit would be a separate authorization, not hidden in this audit.

When gradient-transform inversion fails, original `Gradient::push_stages` has appended `SeedShader` but returns `false` (`gradient.rs:113–123`); original blitter returns `None` before compile/draw (`blitter.rs:79–84,119–124,156–161`). That is a valid no-render outcome, not a reason to run the partial builder as an observed paint pipeline. For successful paint, original `Gradient::push_stages` may add transform only when finite/nonidentity (`pipeline/mod.rs:370–375`), radial pre-stages before spread and lookup, optional premultiply and post-mask (`gradient.rs:125–258`; `radial_gradient.rs:259–311`); capturing after each **original** stage reveals this actual sequence without reimplementing it.

Root should freeze the observer inputs, lifetime/serialization of the recorder, accepted accessible fields, original Source hash guard, and independent unobserved pixel cross-check. No current append-only interleaving can report the private local gradient stop indices; the audit deliberately records that gap rather than fabricating them from a parallel formula. Full gradient sampling, destination gamma/blend/store and backend acceptance remain open.
