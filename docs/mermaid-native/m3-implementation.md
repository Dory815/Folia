# M3 Direct2D consumer implementation report

Implemented only the five authorized new backend files and this report under the committed `m3-direct2d-contract.md`. Root owns feature/module declarations, Windows dependencies, tests, builds, oracle outputs, acceptance and later Folia wiring. This agent ran no builds/tests/commits and changed no portable scene, rendering/parser/layout, manifest, expectation, math, or Folia source. The implementation is ready for independent root compilation/review; no Windows build, pixel parity, resource/HRESULT behavior or backend acceptance is claimed here.

## Lifecycle, output and state

The public API is the frozen `NativeRenderer::new`, `record_scene`, `RecordedScene::dimensions`, `RecordedScene::draw`, and `DrawOptions {transform, clip}`. Renderer creation borrows the supplied device and owns a separate context/factory. It retains canonical device IUnknown identity. Renderer and recorded scene have `PhantomData<Rc<()>>` to keep them thread-confined; CPU scene types are unchanged.

Every record attempt creates its own image-resource table and font-outline caches. No resource id is reused across scenes, no global native cache is present, and no native resource is added to the CPU scene. The final recorded image retains its command lists/effect inputs/brush/geometry/bitmap references through native ownership. A recorded scene retains its original device identity and dimensions independently of renderer/CPU scene lifetime.

Native primitive/text/image resource conversion occurs before publishing any `RecordedScene`. Individual subtree recordings may be built while preparing a later subtree; failures discard all unpublished output. `record` creates a command list, sets the private target, begins its own frame, runs the scoped drawing, ends the frame, detaches the target, resets its transform and closes the command list. EndDraw/Close/interface failures are propagated. When a drawing error and cleanup EndDraw error both occur, the structured error retains both. Geometry conversion preflights numeric segments before opening a sink, balances open contours, and checks sink Close.

The draw method validates options/device before caller state mutation. It pushes its optional destination clip under the original caller transform, sets `original * options.transform` in the frozen affine convention, draws the native image and calls Flush. RAII pops its clip and restores the transform on success/failure. It does not change the caller target, BeginDraw/EndDraw ownership, DPI, unit mode, antialias mode, primitive blend or pre-existing clips. Caller EndDraw remains authoritative after Flush. Native thread/COM and device-loss behavior still require root's actual WARP/hardware tests.

Root viewport clipping is recorded at identity before the completed viewBox mapping. Group clips use converted geometry plus the specified clip transform under the group transform. Raster destination clips are pushed before intrinsic-pixel mapping; glyph image clips/mappings have the same rule relative to final glyph origin. No clip derives a new image fit or changes scene placement.

Errors have a classified `NativeErrorKind`, optional HRESULT, operation, context and retained cleanup failures. Device-loss HRESULTs (D2D target recreation and DXGI removal/hang/reset/internal error) are distinguished from generic native failures, resource failures, unsupported features, numeric conversion failures and device mismatch. No exception/unwrap/panic fallback or swallowed HRESULT was added. Void Direct2D drawing methods are checked through private EndDraw or caller Flush; the native API does not return a synchronous BeginDraw HRESULT.

## Geometry

The backend converts typed rect/rounded rect, circle, ellipse, line, polyline/polygon and Path to native geometry. Rounded x/y radii remain separate and clamp to half their corresponding dimensions; either zero radius gives a sharp rectangle. Lines are hollow figures. Open polygonal/path figures retain stroke openness and native filling semantics. Paths preserve multiple subpaths, Close, continuation after Close, nonzero/even-odd fill, quadratic/cubic contours and elliptical arcs. A zero-radius arc becomes a line, and an equal endpoint arc contributes no arc, matching the primitive semantics. No curve is resampled into a polyline.

All f64-to-f32 conversions reject nonfinite values and overflow with field context. Composed root/group/clip/image/glyph transforms are checked as well as local geometry and font/image data. Rectangle extents and native bounds are checked. Tiny finite values can underflow as part of the native f32 representation; parity thresholds are root-owned. Native geometry bounds are queried using the root-approved GetBounds operation, not a second diagram layout or routing algorithm.

## Paint, gradients and composition

Solid RGBA, fill/stroke opacity, node opacity and group opacity remain separate. Each drawable/group composites once in a native layer; opacity is not multiplied into every descendant paint. Native gradient tables preserve stop order, stop alpha/opacity, endpoints, transforms, spread (clamp/mirror/wrap), sRGB spaces and straight color interpolation. Empty stop tables paint transparently; one-stop/coincident-endpoint gradients use the last stop's color; zero object-box dimensions disable that paint. Object-box mapping is `bbox * gradient.transform`, using local fill bounds excluding stroke.

Stroke conversion preserves start/end/dash cap, join, miter limit, width, dash offset, odd-array repetition and all-zero solid behavior. Native custom dash units are converted by stroke width. Zero-width strokes do not divide by zero or draw. SVG miter uses native miter-or-bevel at the limit, as specified by [Microsoft's SVG join mapping](https://learn.microsoft.com/en-us/windows/win32/api/d2d1svg/ne-d2d1svg-d2d1_svg_line_join).

Ordered normal children are recorded into native command lists. At a multiply child, the preceding completed backdrop and isolated foreground become inputs of a real `CLSID_D2D1Blend` effect with Multiply mode; following children paint over that completed result. This uses actual image composition and preserves painter order, rather than a tint/per-brush alpha approximation. [Microsoft documents the native Blend effect and its alpha composition](https://learn.microsoft.com/en-us/windows/win32/direct2d/blend). Correct source Sankey isolation/pixels, multi-DPI effect realization and transparent-backdrop behavior remain acceptance checks, not inferred from using that API.

## Positioned text

Runs/glyphs are consumed in stored order at `run.origin + accumulated signed advance + glyph.offset`. No bidi reordering, anchor/baseline calculation, measurement, wrapping, shaping or system font replacement occurs. The original font specification/text semantics remain metadata. Retained font bytes/index are parsed with the existing ttf-parser dependency; glyph IDs are checked, and actual contours become typed geometry with preserved line/quadratic/cubic segments, em/upm scaling and inverted font Y axis. Partial failed extraction is discarded.

FontOutline uses the text's effective paint with opacity moved to a single outer text layer. Its gradient uses the aggregate fill bounds of the entire positioned text drawable, not each glyph separately. Ordinary whitespace/control glyphs without outlines contribute no visible geometry. A visible glyph lacking an ordinary outline fails explicitly. Color/raster/font-SVG glyphs declared as FontOutline also fail rather than being silently painted as a monochrome approximation. The `glyph_svg_image` call only detects a font-table representation to reject; it does not parse, decompress, decode or render SVG data.

Retained Geometry and Image appearances are implemented directly. Geometry layers retain their independently resolved local paint; user-space and object-box gradients move with glyph origin and layer transform, using local layer geometry bounds. Image appearances retain their clip and completed mapping relative to the glyph origin. Text outer opacity composites all appearances once. Contour extraction caches are local to the record's text preparation. Source text rotations use group transforms. Sideways glyph runs return `UnsupportedFeature`; no alternate shaping behavior is substituted.

## Images

WIC activation uses the caller's existing COM apartment; the backend neither initializes nor changes that apartment. Owned encoded bytes remain alive in private memory through decode/upload. Decoder creation selects **only** the declared PNG/JPEG/GIF/WebP raster container, avoiding auto-detection that could activate an installed SVG codec. The backend checks container agreement, frame count, decoded dimensions against retained dimensions, premultiplied BGRA format conversion and D2D upload. Upload uses 96-DPI bitmaps so intrinsic pixels map through the supplied scene affine without a DPI-derived refit. Draws preserve alpha, linear interpolation and image-node opacity.

Multiframe encoded images return `UnsupportedFeature` because the immutable resource has no frame-selection/animation policy; no first-frame success silently discards other frames. Missing OS raster codecs and invalid byte streams return classified resource/native errors. C4's two single-frame PNGs are covered by the implemented path but have not been executed by this agent. Image fill/stroke paint properties do not paint raster pixels; effective image opacity and completed mapping/clip are authoritative, and style numerics are still preflighted.

## Decisions frozen during implementation

Root confirmed/pinned windows-numerics 0.2.0 alongside windows 0.61.3, approved native local fill-bound queries, froze all clip coordinate spaces, and froze retained glyph-layer paint spaces versus full-text FontOutline paint bounds. The source uses these exact decisions. Windows generated primary bindings were inspected for the used lifecycle, sink, brush/layer/effect, WIC and COM signatures. No hand-built COM ABI or placeholder font/image geometry was used.

## Missing features and independent evidence still required

Explicit unsupported modes are sideways runs, multiframe images without scene frame policy, and ordinary FontOutline declarations for visible glyphs whose real appearance needs retained color geometry/image data. Actual font variation selection/shaping/fallback remains the upstream resolver's responsibility; this consumer uses retained face default coordinates and explicit appearances, with no variation-axis fields invented. OS codec availability remains a deployment/resource check. There is no generic unknown-node/paint branch or silent omission escape hatch.

Root must independently build the Windows feature and portable feature-off target, then exercise real WARP pixels/state/device identity/resource lifetime/HRESULT cleanup; all primitives/contours/arcs/zero states, nested transforms/clips, gradient spaces/stops/spread, native dash/miter behavior, fill/stroke/group overlap alpha and actual multiply; positioned font/CJK/combining/RTL/color appearances, both C4 PNGs, bad images/fonts/conversions and unsupported modes; 96/120/144/192 DPI and multiple mappings. Preserve untouched reference pixels/expectations and use compiling geometry/paint/text/image mutants to catch omissions. Hardware/device-loss smoke tests and allocation behavior also remain unverified.

M3's source consumer does not complete the remaining M2 scene compilation or SVG extraction, establish full 23-family/options parity, or authorize Folia FFI/worker/cache/editor/PDF wiring. This implementation stops at root review and independent acceptance.
