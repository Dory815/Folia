# P15a oracle and fixture review

Read-only audit of the frozen oracle and generated native fixture against pinned MathJax 4.1.3 `MmlNodes/mmultiscripts.ts` (SHA-256 `bb8d8d2180ef483b86b0b1570b919ba424ed54db1f30ef6e0e697cfab0bf5cf7`) and `docs/math-port/multiscript-contracts.md`. No implementation or acceptance decision is made here.

`node tools/math-port/multiscript-oracle.cjs --check` passes and reports 1,286 assertions, 222 cases, 480 raw-inheritance rows, and 1,161 source-value records. The generated file is 3,383 lines. The oracle verifies the pinned source hash and installed CJS source equality through `multiscript-reference.cjs`; it calls actual MmlMmultiscripts/MmlMprescripts/MmlNone CJS methods for expected outcomes. The custom `Record`, `Probe`, and parent probes are instrumentation subclasses around those real methods, and separate `real_parent_partial` / `real_errors` cases use actual source classes and error handling.

## Concrete gaps for root to consider

| Gap | Evidence in oracle/fixture | Why it matters; a source-derived strengthening |
|---|---|---|
| `mError` receives-options identity is not directly observed. | `error(n,message,options,short)` at oracle line 10 records message/short and, in `fix-mutate`, reads an option value; it mutates a separate global `changingOptions`. C++ `error()` likewise has no identity event. `captured_fix_mutated_after_first_error` proves the original options object is later mutated, but a wrong `mError` argument can still produce the same trace because the helper mutates the global alias regardless of its `options` argument. | In the duplicate-marker test, capture the exact options handle passed into the marker’s `mError` override and assert it is the same object as the `verifyChildren` argument. Also log it in the actual CJS oracle as an identity token, not a structural clone. This checks the contract’s “same options handle” requirement independently of option contents. |
| Live child-array mutation from a script child callback is not exercised. | The reusable `receive()` callback in CJS and C++ only mutates `childNodes` when `name==='base'`; the `sub` callback only mutates the AttributeList under `mode==='alias'`. Existing `rebind`/`grow` cases therefore test the base callback, while marker `isKind`, factory and append have their own cases. | Add a non-base child `setInheritedAttributes` mode that rebinds or grows the owner’s current child array, then verify which subsequent indexes are visited and which array receives final parity repair. This directly covers the contract’s live child-callback mutation row and catches an implementation that rereads before the loop but snapshots during it. |
| Getter access order for duplicate-marker message construction is value-tested but not trace-tested. | Instrumented `Record.kind` is a plain getter with no event; `Probe.kind` is inherited and likewise uninstrumented. The error string can match even if a port reads `this.kind` before `child.kind`. | Add getter-event logging or side effects for `child.kind` and owner `kind`; a duplicate marker should produce the child-kind read before owner-kind read, before the `mError` event, matching `child.kind + ... + this.kind` at source lines 119–123. A mutation-on-read getter can make an order swap observable if plain logging is insufficient. |
| `verifyChildren` callback failures are only represented by a generic throw mode, not distinguishable at each call site. | `mode==='throw'` makes every instrumented `mError` throw the same `WitnessError`; current shape/fix loops do span several sites, but the expected trace does not identify which particular site was configured to throw independently. | Add targeted throwing callbacks for first-marker parity, repeated-marker `child.mError`, final parity, and superclass child verification. For each, assert exactly which later events are absent. This would protect the required return-versus-throw sequencing without relying on incidental shapes that may not reach the intended call site. |

These are coverage proposals, not claims that current results are wrong. The first three directly correspond to explicit frozen-contract requirements; the fourth is a useful discriminator for the same control-flow contract.

## Checks that do appear source-faithful

* The 13 normalization shapes distinguish a first marker at different parities, second marker, pre/post scripts and end repair. The source-value matrix supplies 480 actual method observations across several shapes, raw display/level/prime values, and compares all recorded inheritance tuples.
* The callback cases exercise base rebind/growth, in-place attribute alias mutation, marker `isKind` rebinding, factory rebinding, append-time rebinding, factory null, a null next child, absent base, and null child-array failure. The generated fixture checks event traces, arguments, attributes, tree snapshots, and original array-handle equality where applicable.
* `verifyChildren` cases cover several shapes and `fixMmultiscripts` values, returning/throwing error paths, a dedicated mutation of the captured fix option, and actual `verifyTree`/error-tree paths. Marker/none cases include no parent, ordinary parent, direct multiscripts parent, inferred-row parent, null options, non-null options, children, and real partial errors. The source contract’s direct-parent distinction is reflected in the inferred-row cases.
* The C++ `deep()` helper checks array-versus-object kind, recursively compares own fields, treats NaN as equal and distinguishes `+0` from `-0`. Expected values are freshly generated by the actual-CJS oracle; `--check` confirms the checked-in C++ fixture is byte-for-byte reproducible.

## Unsafe indexing / assertion quality

I did not find an unchecked generated child-vector index in the callback probes: the only helper write to slot 1 is guarded by `size()>1`, and generated `(*n->childNodes)[0]` expressions are created in parent-verification cases that construct exactly one child. The generated source does not use a loose “nonempty only” assertion for the main outcomes: normalization/callback/error cases compare complete event and tree snapshots, and the raw matrix compares complete call rows. `shapeSnapshot` records parent kind rather than parent pointer identity, but the contract’s consequential direct-parent-vs-inferred-parent distinction is separately represented by explicit kind/topology cases.

The oracle is broad and tied to the locked source; the gaps above concern observability of a few explicit obligations, rather than the independence of the expected results. Root should decide whether to add those witnesses before implementation acceptance.
