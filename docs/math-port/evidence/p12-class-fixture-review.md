# P12 raw class-state fixture review

This is a read-only review of the frozen P12 oracle and fixtures. It does not accept the class-state implementation.

The oracle checks the pinned source and executable directly: `MmlNode.ts` SHA-256 `cc0594eb5782928412c4307637866d9f80ac147af577297edd48ee88b63b8656`, resolved `MmlNode.js` SHA-256 `86c5eb572dcf2652c3c52a60b66c720d231e17f600cc9aeef3ace4aeafc81d45`. It also verifies the installed TS copy matches the repository reference. The oracle creates a `Raw` subclass of the locked CJS `AbstractMmlNode`, runs expected behavior against those real methods, and only then emits C++ assertions. The test fixture is reproducible: `node tools/math-port/class-state-oracle.cjs --check` passed and reported 29 values, 1,682 spacing rows, 5,466 assertion slots, and four cases. No build was run.

The 29 raw inputs include `undefined`, `null`, `0`, `-0`, ordinary and TeX class numbers, NaN, Infinity, both booleans, several strings including inherited-property names, empty/one-element arrays, an ordinary object, and an object with null prototype. Raw getter/setter round trips use CJS `Object.is`, so `-0`, NaN, and reference identity are observed correctly. The native helper compares double bit patterns (including signed zero) and shared handles, preserving the same observations. `updateTeXclass` is run for each of the 29 values and the fixture checks both stored raw values and source/target accessor trace order. The spacing matrix covers every pair of the 29 previous/current class inputs at two `prevLevel` settings, with CJS-derived outcomes and traces. Five sequence cases exercise the first `prevClass` nullish read versus a second read when non-nullish.

The important coverage gap is what the matrix's `script` dimension actually varies: it sets `Raw.level` (the previous node's `prevLevel`) to 0 or 1, while `fresh()` always sets the current node's `attributes.scriptlevel` to 0. Therefore it exercises the previous-script-level short circuit and the current-attributes getter when the previous level is falsey, but never the branch where current `scriptlevel > 0` suppresses nonnegative spacing. It also does not exercise relational coercion of raw `prevLevel` values in `texSpacing`; those values are round-tripped through `updateTeXclass`, but the spacing matrix uses only 0/1. Add source-backed cases with current `scriptlevel` positive, and with `prevLevel` values such as null, Missing, NaN, `-0`, numeric strings, booleans, and object handles to validate the `> 0` conversion and its short-circuit trace.

The fixture's `updateTeXclass` calls always pass a truthy node. The upstream method is guarded by `if (core)` (`MmlNode.ts:703-710`), so a null-core no-op witness is absent. Likewise, `setTeXclass` in the raw selection case always receives a truthy previous node, leaving its `getPrevClass(prev)` falsey-argument guard (`MmlNode.ts:716-720`) uncovered. These are small additional branches to witness; the fixture currently validates the non-null transfer and nullish class-selection behavior.

The class-state fixture's empty-node subcase checks numeric NONE for `texClass`/`prevClass` and verifies both setters throw for all raw values. It does not check `prevLevel` there; the independently generated MML fixture does: its pinned `empty_text_readonly_virtual_copy_and_utf16` case checks `prevLevel` getter 0 and read-only failure. The MML and leaf oracle scripts both regenerated cleanly from their locked CJS sources (`mml-node-oracle.cjs --check`: 1,084 assertions/43 cases; `leaf-oracle.cjs --check`: 669 assertions/27 cases). Their generated fixture files are unchanged in the working tree. The current native MML edits change class observations to `Property` and nullish handling; they do not alter the oracle generators or expected fixture values.

One lock boundary remains explicit: `class-state-oracle.cjs` pins the MmlNode TS/CJS files but loads `Tree/NodeFactory.js` without a direct file hash assertion. The factory is used only to instantiate the test classes, while the tested algorithm bodies and expected results come from the pinned MmlNode CJS. If the goal is to lock the complete execution dependency closure, add its CJS hash as well.
