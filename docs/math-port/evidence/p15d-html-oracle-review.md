# P15d read-only oracle review

Reviewed pinned MathJax 4.1.3 `HtmlNode.ts` (SHA-256 `1bf0ba981fc72b63a525424fb51e8bc45231fcf768d618fb8c75517bd72ae665`), `XMLNode` in `MmlNode.ts`, `docs/math-port/html-node-contracts.md`, native `html_adaptor.ixx` / `html_node.ixx`, `tools/math-port/html-node-oracle.cjs`, and generated `tests/math/reference_html_node.cpp`. The source-linked `node tools/math-port/html-node-oracle.cjs --check` succeeds with 306 assertions and 68 cases. This is an evidence review only, not implementation acceptance.

## Source comparison

The seven HTML-specific methods in the contract match `HtmlNode.ts` control flow:

* `getHTML` dispatches through `getXML`, and the oracle includes a virtual `getXML` override with alternate-return and throw cases.
* `setHTML` ignores `getAttribute`'s false/null/undefined result, catches primitive and ordinary exceptions from `getAttribute`, calls `node('span', {}, [originalHtml])` only in the catch, then invokes virtual `setXML` outside the catch. Cases cover null/non-null payloads, a callback that rebinds stored XML during `getAttribute`, wrapping, null/wrapping-node failures, `setXML` throws, and a `setXML` override returning a different XML node. Traces separate the attribute/node/set calls and state assertions check stored XML/adaptor.
* `getSerializedHTML`, `textContent`, and `toString` are each tested for normal host operation, null payload, missing adaptor, XML-only adaptor, host exceptions, and their returned values. `toString` also has a host-kind callback that rebinds XML during the call, so the trace/result can distinguish pre-callback XML from post-callback state.
* `verifyTree` covers absent/token/non-token parents, null and non-null options, and returning/throwing `mError`. The C++ test checks the nullable options handle passed to the override, and the actual inherited empty-error path is separately exercised.
* The token cases call the real inherited `MmlNode.getText()` through a real `mi` node. They cover normal UTF-16 text, a derived `textContent` override with a lone surrogate and supplementary character, a throwing callback, and a payload/adaptor changed after token construction. The native `TextContentBinding` callback is therefore tested as live receiver dispatch rather than a cached text value.
* The copy cases run inherited `XMLNode.copy()` through a factory that creates an HTML subtype. They check a new result object, cloned XML identity, null output adaptor, later serialization failure, clone failure, and missing source adaptor. This reflects the upstream `factory.create(this.kind)` followed by `this.adaptor.clone(this.xml)` and `setXML(clone)` without passing the adaptor (`MmlNode.ts:1536–1541`).

The typed host boundary is appropriately narrow for these methods: opaque shared `XmlRef` preserves payload identity/lifetime; `HtmlAdaptor` adds the five source-required HTML calls; UTF-16 is retained for text content; and no browser/Windows API leaks into the core declaration. `setHTML`'s native return type `XMLNode*` is necessary to observe the source virtual `setXML` result without introducing a cast failure. The XML-only adaptor cases are useful checks that missing HTML host methods surface as errors rather than being silently substituted.

## Oracle gaps that could strengthen acceptance

| Gap | Current observation | Suggested source-derived witness |
|---|---|---|
| Factory-before-clone order in inherited copy is not observed. | In `copy_clone-throw`, the source adaptor trace contains `clone/original`, and the call fails. The oracle's `factory()` returns an ordinary `MmlFactory` with class bindings only; its `create` is not traced. Thus it cannot tell whether the copy target was created before or after `clone` throws, although upstream evaluates `this.factory.create(this.kind)` first. | Use an instrumented source `MmlFactory` subclass whose `create` logs the kind and returns the same registered subtype. For success and clone-throw, assert the call sequence is `factory.create(html)` then `clone(xml)` and that no `setXML` follows a clone throw. |
| Copy-created `TextContentBinding` receiver is not tested. | `copy_normal` checks the clone and null adaptor, then checks failed HTML serialization. Real token tests exercise the original instance, not a copy. The constructor-installed native callback should bind to the new object, not the source object. | After copy, call virtual `setXML(other, &host)` on the clone, place it under a real token node, and call token `getText()`. Assert the callback reads the clone's new payload via the clone's adaptor and does not dispatch to the source instance. |
| Freshness/identity of `setHTML`'s literal arguments is reduced to shape. | The adaptor logs `Object.keys(a).length`, `c.length`, and `id(c[0])`; the native host logs key/count/element id. This proves empty attributes and a one-element list with the expected payload label, but not that each wrapping call receives a fresh `{}` and fresh `[html]` object, or that the exact object reference is passed when distinct objects can share a label. | Have one CJS adaptor capture each `a` and `c` reference across two wrapping calls on the same host, then assert exact payload reference and pairwise fresh record/list identities. The typed host may deliberately adapt these to values, but the oracle should state which identities its boundary promises to preserve. |
| Omitted `setHTML` adaptor parameter is not called directly. | `set_host_null` passes explicit `null`; all other set cases pass an adaptor. The TypeScript default applies when argument is omitted or `undefined`, and the native declaration has a `nullptr` default. | Add a source call `setHTML(html)` (and, if the selected wrapper can express it, explicit `undefined`) to pin default-argument behavior at the bridge. This is low risk because default `null` is visible in both source and native declaration, but the current fixture only tests explicit null. |

The first two copy cases matter most for the contract's ordering and constructor-bound callback claims. The argument-reference case is only needed to the extent root intends the native typed adaptation to promise object/list identity; the current contract names “fresh node arguments,” so structural-only checks leave that phrase ambiguous. The omitted-argument case is a small API-boundary witness rather than a source-algorithm gap.

## Error boundaries and return identity

The CJS `caught` helper records thrown `Error.name` or primitive type; the C++ `caught` helper maps `FactoryError`, standard exceptions, and integer throws to corresponding names. This is sufficient for the explicit `HostError`, missing-method `TypeError`, foreign `Error`, and primitive-number witnesses in the fixture. `setXML` failure is separated from the `getAttribute` catch path: the expected trace can establish that it propagates and does not trigger span wrapping. The adaptor return values false, null, and undefined are all separately exercised, so replacing the ignored return with a truthiness test should fail.

The payloads `original`, `wrapped`, `other`, and `late` have distinct labels. Assertions on XML state and virtual `setXML` return distinguish the source object, the span wrapper, state rebound inside an adaptor callback, and an alternate returned receiver. This is strong for the concrete fixtures. Since the trace serializes identity by labels rather than recording an opaque identity token, an implementation that substitutes a different object carrying the same label would not be rejected; the current CJS adaptor only constructs the known objects, so this is a theoretical limitation rather than a present case collision.

## Remaining scope boundary

The oracle validates the seven `HtmlNode` methods and the inherited XML copy/text extraction behavior that this packet calls. It does not test enabled `texhtml` parsing, arbitrary DOM parsing/serialization, `HtmlNode` SVG foreign-object layout/measurement, MathML input, or HTML sanitization. The contract correctly keeps those as separate required integrations; the profile's disabled `allowTexHTML` case is not evidence of enabled-path support. No changes to source, interfaces, oracle, fixture, or tests were made in this review.
