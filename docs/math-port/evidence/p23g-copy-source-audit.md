# P23g — `AbstractMmlNode.copy` Source and old-observer audit

Read-only audit of pinned MathJax 4.1.3 `AbstractMmlNode.copy`, the actual-factory Source299 corpus, and the historical native MML test observer. It identifies copy's source order and observer type seams; it does not implement copy, authorize gold changes, or claim Source coverage is complete. No build, test, or experiment was run.

## Source implementation and evaluation order

Pinned `.reference/MathJax-src/ts/core/MmlTree/MmlNode.ts` (`AbstractMmlNode.copy`, lines 467–492; SHA-256 `cc0594eb5782928412c4307637866d9f80ac147af577297edd48ee88b63b8656`) is the authority. The installed CJS from the exact locked bundle (`tools/mathjax-bundle/node_modules/@mathjax/src/cjs/core/MmlTree/MmlNode.js`, lines 149–191; SHA-256 `86c5eb572dcf2652c3c52a60b66c720d231e17f600cc9aeef3ace4aeafc81d45`) shows the transpiled execution sequence.

The body proceeds in this order:

1. `keepIds` defaults to `false` only for an omitted/undefined argument. It calls `this.factory.create(this.kind)` and stores the new MML node before reading the source node's properties, attributes, or children. Constructor work and virtual factory registration therefore happen first.
2. It assigns `node.properties = { ...this.properties }`. The target receives a fresh shallow object. Enumerable own top-level values are copied; nested object/array values remain the same Source identities. This is distinct from sharing the whole `properties` object.
3. It checks `this.attributes` for truthiness, reads it again to call `getAllAttributes()`, then computes `Object.keys(attributes)`. `Attributes.getAllAttributes()` in pinned `Attributes.ts:222–224` returns the raw explicit-attributes object, not a clone of defaults/inherited/global layers. `Object.keys` snapshots the own enumerable string keys. For each captured key, it tests `name !== 'id' || keepIds`; if selected, it evaluates `node.attributes.set(name, attributes[name])`. Thus the destination's `attributes` and `set` receiver are read before the per-key source value Get; the source value is fetched live for that key immediately before the call. `id` is omitted by default. Only this node's `keepIds` argument is honored: recursive children are called as `child.copy()` with no argument, so their IDs use the child method's default `false`.
4. It tests `this.childNodes` and then `this.childNodes.length`. If nonempty, it captures `this.childNodes` into local `children`. When the captured length is exactly one, it reads `children[0].isInferred`; this is an unguarded property access before the loop. If inferred, it reads `children[0].childNodes` and replaces the local iteration handle with that inner array. A singleton hole/Undefined or explicit Null therefore throws at `isInferred` before the falsey-child loop; it is not silently copied as Null.
5. It iterates the chosen array with `for...of`, which captures that array object and sees its live length. A truthy yielded child receives virtual `copy()`; only after that returns does the fresh copy receive virtual `appendChild(copiedChild)`. A falsey yield—hole/Undefined, Null, or another falsey value—is written as a *present explicit Null* by direct `node.childNodes.push(null)`. That branch bypasses `appendChild`, so it has no child-parent assignment. In-place source changes affect the captured iterator; rebinding the original node's `childNodes` does not redirect it. Destination append overrides may reshape the destination independently.
6. It returns the factory-created node. The method does not clone the `Attributes` layers wholesale, pass `keepIds` recursively, preserve a hole as a hole, or use `NodeUtil.setChild`.

The CJS and TypeScript bodies agree on the significant sequencing. The CJS emitted `__assign({}, this.properties)` is the bundle's transpilation of the source object spread. `Attributes.ts` SHA-256 is `c1e363944e0c059c7ed554b4b6aeb8ea56d43c844f84934c267ccc79b090468a`; `getAllAttributes` is a raw-store accessor, and `Attributes` construction creates separate defaults/inherited/explicit prototype layers (lines 63–69). No production MathJax class declares `attributes` as a getter; any side-effecting attribute accessor must be described as an observer/injection binding, not a normal copy-path callback. Source order still matters for getter-capable JavaScript objects and for native virtual accessors if Root explicitly includes them in the bounded contract.

## Actual-factory cases in Source299

`docs/math-port/evidence/p23b-sparse-mml-source.json` is the frozen 299-case original-MathJax MML corpus (SHA-256 `b9717d5f5213ad400617fb680f92d3f744cae0b7f7b2182f86a194b205367ab4`). Its generator `tools/math-port/sparse-mml-oracle.cjs` (SHA-256 `5abbafb661a571520081bf91c19aad208e49484c0f3316a8910037445d64a387`) constructs an `ObservedFactory extends MmlFactory`, calls the real pinned registry and classes, and records actual identities/arrays/parents/errors. The factory/source pins include `MmlNode.js`, `MmlFactory.js`, `MML.js`, `mrow.js`, `msubsup.js`, `mfrac.js`, and NodeUtil. The named MML-copy cases are:

| Case family | Count | Binding and coverage |
|---|---:|---|
| `copy-mrow-{shape}`, `copy-msubsup-{shape}`, `copy-mfrac-{shape}` | 75 | Three actual factory node kinds × the 25 length-three layouts made from leading/middle slot states `H`, `U`, `N`, `a`, `b`, with final child `c`. Covers holes, Undefined, Null, and Node combinations through each class's inherited MML `copy`. |
| `inferred-copy-{shape}` | 25 | Actual `math` node with actual inferred row, same 25 shapes. Exercises the one-child inferred-row flattening branch using the factory-created class graph. |
| `copy-single-{H,U,N,a}` | 4 | Actual `mrow` with one hole, Undefined, Null, or Node. The three nullish cases error while reading `.isInferred`; a Node case can proceed. |
| `copy-live-child-{append,delete,shrink,rebind}` | 4 | Actual MML copy with a child `copy` callback mutating or rebinding the source array. Verifies captured-array/live-length behavior and destination results. |
| `superscript-first-copy` | 1 | Actual `msubsup.copy` with a superscript-first sparse layout. Setup uses the original `NodeUtil.setChild` to create that input state; the observed copy itself is the real MML `copy` call. Do not count this as an isolated NodeUtil or generic helper copy witness. |

That is 109 cases invoking actual MML `copy`. The separate `superscript-first-copyChildren` case invokes `NodeUtil.copyChildren`; it is excluded from the MML-copy count. The source oracle has other cases whose names mention copy-related lifecycle, but they are not calls to `AbstractMmlNode.copy` and should not be represented as such. The two principal fixture sources are the actual MML Source JSON and its pinned CJS generator; hashes are in the evidence table.

Two concrete source outputs establish the otherwise easy-to-confuse null branches. `copy-mrow-H-N-c` has a source array with a hole, then explicit Null, then Node; the returned mrow has three own slots `[Null, Null, copied Node]` and no error. `copy-single-N` throws `TypeError: Cannot read properties of null (reading 'isInferred')` before iteration. `inferred-copy-H-N-c` preserves the same falsey-to-Null behavior while flattening the actual inferred row. This is direct evidence from the frozen Source corpus, not an inferred expectation.

## Historical MML observer: signature/storage changes versus Source semantics

`tests/math/reference_mml_node.cpp` (SHA-256 `a34004baa7ead53796eee175c2e4015aa025af70562487e5273d1c1dac8eac25`) is explicitly a generated expectation file (“Do not edit”, line 1). Its leading observer API (lines 7–14, 23, 30–32) uses `shared_ptr<vector<MmlNode*>>`, raw parent pointers, `at()` that maps out-of-range/Null to the same `nullptr`, a `kinds()` helper that emits the same text for Null and absent, pointer-based `setTeXclass`, and raw pointer child callbacks. Those are stale native storage/access signatures and must be adapted to ChildArray/ChildValue and the frozen virtual API. This adaptation should preserve identity checks while making holes, Undefined, Null, and out-of-range distinguishable in the observer.

Copy-related historical assertions do **not** all conflict with Source:

| Existing observer location | Existing expectation | Source evidence and classification |
|---|---|---|
| Lines 92–101 | `copy(true)` keeps the root id but child copy has no id; inherited `mathsize` is not copied as explicit; a second explicit-null child is copied as a null slot. | These match the Source body: `keepIds` is used only for the current node, `getAllAttributes()` returns only the explicit store, and a falsey child in an array longer than one is appended as explicit Null. Preserve the semantic gold after changing the observer types. |
| Lines 106–109 | A child-copy callback appends a sibling; copied inferred row observes it and parent identity is checked. | This is source-supported captured-array/live-length behavior, though the dense helper only checks node cases. Retain the scenario and update its array adapter. |
| Line 110–111 | Nested property value compares equal after copy. | This is consistent with fresh shallow `properties` object plus shared nested Property identity. Do not change the expected alias semantics without a Source counterexample. |
| Lines 98–100 | Input gets a second explicit Null; result count is two and `at(copy,1)==nullptr`. | Source299 has the same falsey-to-explicit-Null operation. Re-express the assertion as an own present slot tagged Null; `nullptr` is only the old observer encoding. |
| Lines 1991–1994 | Singleton Null causes `copy()` TypeError; `setInheritedAttributes` and `verifyTree` also error. | For copy, Source299 `copy-single-N` confirms the exact `.isInferred` TypeError before iteration. The two other errors follow their own unguarded child calls. These are not grounds for deleting the gold. |
| Line 88–89 | `appendChild(nullptr)` throws and the child count remains one. | This receiver is `AbstractMmlNode` with default `arity === Infinity`, so the MML override runs first and reads `child.isInferred` before delegating to generic `Node.appendChild`; Null therefore throws before the array is mutated. The pinned CJS at `MmlNode.js:303–333` has the same order. Keep this separate from two other paths: generic `Node.appendChild` (`Node.ts:263–267`) pushes before setting `child.parent`, and MML's inferred-row flatten branch calls that generic operation on each flattened element. Source299 case `append-inferred-mrow-N-H-c` records `Cannot set properties of null (setting 'parent')` from this flatten route; it does not contradict the direct MML `child.isInferred` failure. The frozen corpus has no direct `appendChild(null)` case, so that exact direct outcome follows pinned method order, not a claimed matching Source299 row. |

The test helper cannot currently create a hole or a present Undefined because `children(...)` builds a dense vector of pointers. Thus a `nullptr` in these legacy golds means explicit Null in setup; it cannot serve as evidence for a hole or Undefined expectation. Helpers `count`, `at`, and `kinds` also collapse states, so assertions using them are under-discriminating when the new API is introduced; improve the observation representation without rewriting correct Source values. The Source299 families `copy-mrow-H-N-c`, `copy-single-H`, `copy-single-U`, and `copy-single-N` supply the distinctions absent from this old fixture.

Other historical native MML observers in `tests/math` share type seams rather than a license to alter their expected values. The files that still use dense `std::vector<MmlNode*>` child storage, raw `parent`, or old raw-pointer child/callback signatures are `reference_maction.cpp`, `reference_arithmetic.cpp`, `reference_arithmetic_order.cpp`, `reference_atom_semantics.cpp`, `reference_html_node.cpp`, `reference_inheritance_boundary.cpp`, `reference_leaf.cpp`, `reference_mathchoice.cpp`, `reference_mfenced.cpp`, `reference_mml_node.cpp`, `reference_mml_registry.cpp`, `reference_mo.cpp`, `reference_mo_order.cpp`, `reference_mo_values.cpp`, `reference_multiscript.cpp`, `reference_script.cpp`, `reference_simple_mml.cpp`, and `reference_table.cpp`. Adapt only those actual child stores and parent/callback observations; keep expected values unless a pinned Source case proves a mismatch. Where an old dense test deliberately uses `nullptr`, preserve it as explicit Null; where a test only checks `nullptr`, decide whether that is intended Null or an imprecise absent-state assertion from the fixture's setup before changing its gold.

Four nearby files are not stale dense MML observers and should not be included in that inventory: `reference_mml_append.cpp` and `reference_mml_constructor.cpp` are newer actual-Source suites whose `std::vector<MmlNode*>` fields (`nodes`/`adopted`) register factory object identities; their child storage is `ChildArray`/`ChildValue`. `reference_factory.cpp` tests the generic factory creator map and has no MML child tree. `reference_tree.cpp` tests the generic tree with `ChildArray`/`ChildValue` and tagged parents; its `std::vector` fields hold traces/registry observations rather than child storage. In particular, generic `reference_tree` copy has different Source behavior (generic `Node.copy` skips falsey children), so do not copy the MML copy rule into generic tree expectations. `reference_sparse_node.cpp` also already uses `ChildArray`/`ChildValue` and is not part of the stale dense-observer list.

Within the copy assertions reviewed here, no expectation has yet been shown to conflict with pinned Source. The material issue is representational: dense helpers cannot express or distinguish the sparse cases that Source299 covers, and the old `nullptr` comparisons under-specify states. Keep the existing expected results until Root's bound Source copy fixture demonstrates a mismatch; add discriminating observations instead of silently rewriting golds.
